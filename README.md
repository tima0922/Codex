# Tima Assistant

Личный Telegram-бот и Mini App: расписание, рабочие смены, задачи, личные финансы и уведомления. Интерфейс — React + TypeScript, сервер — Cloudflare Worker, база — Supabase Postgres. Время везде Asia/Tashkent (UTC+5).

## Уже реализовано

- Главная с ближайшим событием, лентой дня и конфликтами пар со сменами.
- Календарь с редактором конкретных дат: пары, смены через полночь, личные события.
- Задачи, сроки, приоритет и завершение из Mini App или кнопкой в боте.
- Доходы, расходы, платежи и их оплата. Остаток — доходы минус расходы и оплаченные платежи за текущий месяц, не банковский баланс.
- Выключатели уведомлений, интервалы, тихие часы, необязательные обзоры в 07:00 и 20:00.
- Первая пара заранее; в конце каждой пары — следующая аудитория или сообщение об окончании учебного дня; смена заранее; задачи до срока; платежи в 10:00.
- Бот: `/start`, `/today`, `/tomorrow`, `/week`, `/work`, `/tasks`, `/add текст`, `/settings`, `/help`.
- Общая база для бота и интерфейса. Проверка подписи Telegram initData, срока авторизации и числового ID владельца. Токен бота, секрет базы и данные расписания не входят в клиентскую сборку.
- Демо на публичной странице содержит только вымышленные примеры и хранит изменения в памяти текущего окна.

## Развёртывание

Репозиторий подключён к Cloudflare Workers Builds. `wrangler.jsonc` сохраняет имя существующего Worker `codex`, собирает интерфейс через `npm run build` и объявляет Cron Trigger раз в минуту. Cloudflare устанавливает зависимости из lockfile. При ручном запуске: `npm ci` и `npm run deploy`.

Supabase: `https://supabase.com/dashboard/project/dnxytuqhbhoyfwqydnsn`.
Схема находится в `supabase/migrations/`. Начальные личные расписания импортируются напрямую в базу, не хранятся в публичном Git.

В Cloudflare → Worker `codex` → Settings → Variables and Secrets нужны:

| Имя | Значение | Тип |
| --- | --- | --- |
| `BOT_TOKEN` | Токен от BotFather | Secret |
| `SUPABASE_SECRET_KEY` | Серверный `sb_secret_...` из Supabase Settings → API Keys; допускается legacy `service_role` | Secret |
| `OWNER_TELEGRAM_ID` | Числовой Telegram ID владельца, установленный после проверки его сообщения боту | Secret |
| `WEBHOOK_SECRET` | Случайная строка 32+ символа: A–Z, a–z, цифры, `_`, `-` | Secret |

`SUPABASE_URL` и `APP_URL` уже объявлены как обычные переменные. После добавления секретов нажать Deploy. `/health` должен возвращать `configured:true`.

Далее выполнить `npm run setup-bot`: скрипт запросит токен и тот же webhook-секрет скрытым вводом, настроит команды, описание, кнопку приложения и защищённый webhook. Не вставлять секреты в shell-команды или исходники. Для локальной разработки допускается игнорируемый `.dev.vars`.

## Приватность и надёжность

Таблицы имеют RLS и отозванные права у `anon` и `authenticated`. Отсутствие публичных RLS-политик намеренно: доступ к базе только из Worker с серверным ключом после проверки Telegram ID. Информационное замечание Supabase `RLS Enabled No Policy` соответствует этому решению. Функция атомарного резервирования уведомления доступна только `service_role`, использует `SECURITY INVOKER` и фиксированный `search_path`.

Webhook принимает только правильный `X-Telegram-Bot-Api-Secret-Token`, личные сообщения и ID владельца. Автоматической привязки к первому пришедшему пользователю нет. Содержимое запросов и ключи в журнал не пишутся.

Уведомления рассчитываются каждую минуту. Догоняем задержку до пяти минут, пытаемся доставить до четырёх раз, сохраняем ключ доставки в базе. После изменения или удаления события план вычисляется заново. При сбое между успешной отправкой Telegram и отметкой в базе возможен повтор — гарантия exactly-once у Bot API отсутствует. Если Worker/БД недоступны дольше пяти минут, старые уведомления пропускаются. Тихие часы подавляют сообщения без последующей пачки.

Расписание хранится по датам, автоматического доступа к HEMIS и фоновой синхронизации Google Drive нет. Чтобы обновить, отредактировать события в календаре либо импортировать проверенные новые даты напрямую в базу. Платежи пока разовые; автоповтор ежемесячных платежей не реализован.

## Проверки и структура

`npm test` — подписи, владелец, устаревшие/поддельные данные, webhook, ночные смены, аудитории на перемене, тихие часы, дедлайны, платежи и валидация. `npm run build` — сборка Mini App.

- `app/main.tsx`, `app/style.css` — интерфейс.
- `src/index.js` — API, бот, Cron Trigger и доступ к базе.
- `src/core.js` — авторизация, даты, план уведомлений и валидация.
- `scripts/setup-bot.mjs` — настройка Bot API скрытым вводом.
- `scripts/build.mjs` — сборка статических ресурсов.

Резервные копии личных данных делаются средствами базы; репозиторий содержит только код и схему. Бесплатные тарифы зависят от лимитов и правил хостинга; мониторинг и оплачиваемые услуги здесь не подключаются.
